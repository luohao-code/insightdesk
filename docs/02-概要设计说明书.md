## 1 设计目标

在满足《软件需求规格说明书》全部 P0/P1 需求的前提下，优先保证：

1. **可运行**：零外部依赖即可启动，无密钥也能完整演示；
2. **可扩展**：OCR 与 AI 引擎可插拔，新增平台不改业务代码；
3. **可稳定**：批量 100 张不崩溃，失败可定位、可重试；
4. **可维护**：后端分层清晰，前端按页面/组件拆分，测试覆盖核心链路；
5. **可交付**：同时支持 Web、Docker 与 Windows 桌面三种形态。

## 2 总体架构


## 4 关键技术决策

### 4.1 为什么用原生 ES Module，而不是 React/Vue

- 课程要求"综合运用多种技术与平台"，原生模块能体现对浏览器能力的直接掌握；
- 无 npm 构建步骤，部署只需静态文件，离线可用；
- 通过设计令牌与组件封装控制复杂度，避免"无框架即无结构"。

**代价**：需要自行实现路由、状态与组件生命周期；通过 `router.js`、`store.js` 与统一 `el()` 工具控制成本。

### 4.2 为什么用线程池而不是 Celery

单机单用户场景下，引入 Redis + Celery 会显著增加部署复杂度。项目采用：

- 每批次一个 `ThreadPoolExecutor`，最大并发 1–8；
- 单任务指数退避重试；
- 批次状态持久化，服务重启后标记为可重试；
- 事件总线 + SSE 推送进度。

该方案满足 100 张图片的稳定性要求，且零额外中间件。

### 4.3 为什么用 SSE 而不是 WebSocket

进度是**单向、低频、可重连**的推送，SSE 更简单：浏览器原生 `EventSource` 自动重连，服务端只需输出文本流；断线时前端降级为 4 秒轮询。

### 4.4 为什么用 FTS5 trigram

中文没有空格分词，默认 unicode61 分词器无法按子串检索。trigram 分词器支持中文子串匹配，且无需引入 jieba 等分词依赖；查询长度小于 3 时自动降级 `LIKE`。

### 4.5 演示引擎与自动降级

没有密钥或未安装 RapidOCR 时，系统自动使用演示引擎，保证"功能流程完整可演示"；界面明确标注"演示结果"，避免误解。降级策略：

```text
显式请求引擎 → 设置中的默认引擎 → 演示引擎
```

每次降级都会在结果中返回 `notice`，前端以黄色提示条展示。

## 5 核心数据流

### 5.1 单图识别

```text
浏览器上传 → image_service 校验/落盘/缩略图
          → ocr_service 选择引擎（可用性检查）
          → 可选预处理（灰度/对比度/旋转/限宽）
          → Provider.recognize → 标准化 OCRResult
          → 文本后处理（清洗、软换行合并）
          → 写入 documents → 返回文本与元信息
```

### 5.2 批量识别

```text
创建批次（校验图片、写入 tasks）
  → start_batch 建立线程池
  → 每个 worker：标记 running → 调 OCR → 成功/失败计数（原子自增）
  → 事件总线广播 → SSE 推送前端
  → 全部结束 → _finalize_batch 计算最终状态
```

### 5.3 网页提取与自动打开

```text
URL 校验（协议/端口/主机/解析地址）→ 逐跳抓取（限制大小与超时）
→ BeautifulSoup 清理噪音 → 容器打分 → 正文/元数据/图片
→ 保存 web_extractions → 可选转为 documents
→ 桌面模式调用系统浏览器；Web 模式前端新标签页打开
```

## 6 安全设计

| 风险 | 措施 |
| --- | --- |
| SSRF | 仅 http/https；禁止内网/环回/链路本地/保留地址；逐跳校验重定向；限制端口 |
| 密钥泄漏 | 仅服务端存储；接口返回掩码；提交掩码表示保持原值；CI 扫描硬编码 |
| 路径穿越 | 上传文件随机 ID；`safe_join` 校验；数据库只存相对路径 |
| XSS | 用户文本统一 `textContent`；少量 HTML 拼接前转义 |
| 资源耗尽 | 文件大小、响应体大小、任务数量、并发数均有限制 |
| 错误信息泄漏 | 统一异常处理，不返回堆栈；详细日志写本地文件 |

## 7 性能与容量

| 指标 | 设计值 | 说明 |
| --- | --- | --- |
| 单图识别 | ≤ 3 秒（本地/演示） | 云端取决于网络 |
| 批量吞吐 | 100 张 ≤ 10 分钟 | 并发 3、云端限流时自动退避 |
| 历史检索 | ≤ 500ms（1 万条） | FTS5 索引 |
| 内存占用 | 空闲 ≤ 200MB | 图片处理采用流式与缩略图 |
| 数据库 | 单文件，WAL | 支持万级记录 |

## 8 扩展点

1. **新增 OCR 引擎**：实现 `OCRProvider`，在 `providers/ocr/__init__.py` 注册；
2. **新增 AI 平台**：复用 `OpenAICompatibleProvider` 预设，或实现 `AIProvider`；
3. **新增导出格式**：在 `export_service` 增加 builder 并登记格式；
4. **新增页面**：在 `frontend/js/pages/` 新建模块，在 `app.js` 注册路由；
5. **替换数据库**：SQLAlchemy 支持 PostgreSQL，只需调整连接串与 FTS 实现。

## 9 风险与对策

| 风险 | 对策 |
| --- | --- |
| 云端 OCR/AI 限流 | 默认并发 3、指数退避、失败原因可视化 |
| 动态网页无法提取 | 文档说明限制，后续可接入无头浏览器 |
| 打包缺少 DLL | 提前试打包、收集 uvicorn 子模块、提供构建脚本 |
| 前端零构建导致模块增多 | 统一组件接口、按页面拆分、CI 语法检查 |
| SQLite 并发写 | WAL + busy_timeout + 原子更新计数 |
