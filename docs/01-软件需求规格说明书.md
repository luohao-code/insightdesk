## 1 引言

### 1.1 编写目的

本文档定义"识文台 InsightDesk"（以下简称"本系统"）的软件需求，作为项目设计、开发、测试与验收的共同依据。预期读者为项目组成员、课程指导教师、测试人员以及后续维护者。

本文档遵循 IEEE 830 需求规格说明的组织方式，描述系统的功能需求、非功能需求、外部接口、数据需求与验收标准，并建立需求追踪关系，确保"需求—设计—实现—测试"可追溯。

### 1.2 项目背景

在课程学习、文献整理、资料归档与日常办公中，大量有价值的信息以图片形式存在（扫描件、课件截图、书页照片、聊天截图、网页长图）。人工逐字录入效率低、易出错；而通用 OCR 工具往往只提供"识别"能力，缺少后续的翻译、摘要、关键词提取、历史管理与结构化导出，识别结果也难以二次利用。

本项目面向"轻量、可自部署、可扩展"的场景，构建一款 **基于 Web 的 OCR + AI 文字处理工作台**：用户导入图片或网页链接，系统通过 OCR 引擎提取中英文印刷体文字，再调用大语言模型完成翻译、总结、关键词与问答，最终形成可编辑、可检索、可导出的个人文字资产库。系统同时提供桌面启动器，双击即可启动本地服务并**自动打开浏览器**，兼顾 Web 应用的可访问性与桌面软件的易用性。

### 1.3 项目范围

**本系统包含：**

1. 图片导入与预处理（单张、多张、文件夹、拖拽、剪贴板粘贴）。
2. 中英文印刷体 OCR 识别，支持本地引擎与云端引擎可插拔切换。
3. 识别结果的编辑、复制、分段与基础后处理。
4. 批量任务队列：并发限流、实时进度、失败重试、任务取消。
5. AI 能力：翻译、摘要、关键词提取、基于文本的问答。
6. 历史记录：持久化存储、全文检索、筛选、收藏、删除。
7. 导出：TXT、CSV、Markdown、Word、Excel、ZIP 批量打包。
8. 网页内容提取：抓取标题、正文、作者、站点与图片，并可一键送入 OCR / AI 流程。
9. 提取完成后自动打开原始网页；桌面启动器启动后自动打开系统默认浏览器。
10. 设置中心：引擎选择、密钥管理、并发与重试参数、主题与语言。
11. 运行看板：识别量、成功率、耗时、引擎使用分布等统计。
12. 桌面打包：通过 PyInstaller 生成 Windows 可执行程序。

**本系统不包含（明确排除）：**

- 本地离线大模型的训练与推理部署；
- 复杂表格结构还原、公式识别、手写体识别；
- 自动排版与自动生成报告文档；
- 视频理解与音频转写；
- 自研 OCR 模型训练；
- 多用户账号体系、在线支付、云端同步。

### 1.4 术语与缩略语

| 术语 | 说明 |
| --- | --- |
| OCR | Optical Character Recognition，光学字符识别 |
| LLM | Large Language Model，大语言模型 |
| 引擎（Provider） | 提供 OCR 或 AI 能力的具体实现，如 RapidOCR、百度 OCR、DeepSeek |
| 批次（Batch） | 一次批量识别任务，包含若干图片任务项 |
| 任务项（Task） | 批次中的单张图片识别作业 |
| SSE | Server-Sent Events，服务器推送事件，用于实时进度 |
| SSRF | Server-Side Request Forgery，服务端请求伪造 |
| 工作台 | 单图识别与结果编辑的主界面 |

## 2 总体描述

### 2.1 产品前景

系统定位为"个人与小团队的轻量文字资产工作台"。与纯 OCR 工具相比，本系统强调**识别后的智能加工与资产管理**；与大型文档管理系统相比，本系统强调**部署简单、零学习成本、可离线运行**。系统采用 B/S 架构，浏览器即客户端；同时提供桌面启动器，将 Web 应用封装为"双击即用"的本地软件形态。

### 2.2 产品功能概览

```text
┌──────────────────────────────────────────────────────────────┐
│                        识文台 InsightDesk                     │
├───────────────┬────────────────┬───────────────┬─────────────┤
│  输入层        │  处理层         │  智能层        │  资产层      │
│  图片上传      │  OCR 识别       │  翻译          │  历史记录    │
│  批量文件夹    │  图像预处理     │  摘要          │  全文检索    │
│  剪贴板截图    │  文本后处理     │  关键词        │  收藏/标签   │
│  网页链接      │  任务队列       │  问答          │  多格式导出  │
└───────────────┴────────────────┴───────────────┴─────────────┘
```

核心业务主线：**选图/取网页 → OCR → 文本 → AI 处理 → 显示/复制/导出 → 存入历史**。

### 2.3 用户特征

| 用户类型 | 特征 | 主要诉求 |
| --- | --- | --- |
| 学生 | 需要整理课件、论文、书籍截图 | 快速识别、翻译、摘要、导出复习资料 |
| 教师/研究人员 | 资料量大，重视检索与归档 | 批量处理、历史检索、结构化导出 |
| 办公人员 | 非技术用户，要求开箱即用 | 一键启动、界面直观、失败可重试 |
| 开发者 | 关注可扩展性与接口 | 引擎可插拔、REST API、可二次开发 |

系统为单用户本地应用，不区分账号角色；如部署在局域网，可通过访问令牌限制调用。

### 2.4 运行环境

| 项目 | 要求 |
| --- | --- |
| 服务端 | Python 3.10+（推荐 3.12），Windows 10/11、Ubuntu 20.04+、macOS 12+ |
| 浏览器 | Chrome/Edge 100+、Firefox 100+、Safari 16+ |
| 数据库 | SQLite 3（默认，文件型，零配置） |
| 网络 | 本地功能可离线；云端 OCR/AI 需可访问对应服务 |
| 硬件 | 双核 CPU、4GB 内存即可运行；本地 OCR 建议 8GB 内存 |
| 可选组件 | rapidocr-onnxruntime（本地 OCR）、PyInstaller（打包） |

### 2.5 设计与实现约束

1. 采用 B/S 架构，前端为浏览器单页应用，后端提供 REST API。
2. 后端使用 Python + FastAPI，数据层使用 SQLAlchemy + SQLite。
3. 前端不依赖构建工具与外部 CDN，保证离线可用与部署简单。
4. 密钥不得硬编码在前端或打包产物中，统一由服务端读取本地配置。
5. 所有外部网络请求必须设置超时，并对网页抓取实施 SSRF 防护。
6. 代码总量不少于 15000 行（不含第三方库与自动生成文件），满足课程规模要求。
7. 按阶段提交软件产品与文档，使用 Git 进行版本管理与协作。

### 2.6 假设与依赖

- 假设用户具备可用的云端 OCR/AI 密钥，或在本地安装 RapidOCR；否则系统使用内置演示引擎，功能流程完整但识别/生成结果为模拟数据。
- 假设运行环境可写入应用数据目录（默认为项目下 `data/`）。
- 依赖开源组件：FastAPI、SQLAlchemy、Pillow、BeautifulSoup、python-docx、openpyxl 等。

## 3 功能需求

需求优先级定义：**P0** 必须实现（验收阻断项）；**P1** 应当实现；**P2** 可选增强。

### FR-01 图片导入（P0）

**描述**：用户可将待识别图片导入工作台或批量队列。

**输入**：本地图片文件（PNG/JPG/JPEG/WEBP/BMP/TIFF）、文件夹（桌面模式下选择目录）、剪贴板图片、拖拽文件。

**处理**：
1. 校验扩展名、MIME 类型与文件大小（单文件默认 ≤ 20MB）；
2. 使用 Pillow 校验图片完整性，读取宽高与模式；
3. 生成缩略图并保存至上传目录；
4. 单图模式返回图片标识，批量模式创建批次与任务项。

**输出**：图片元数据（标识、文件名、尺寸、大小、预览地址）。

**验收标准**：可一次选择 100 张图片，全部入队且界面列表完整显示；非法文件被拒绝并给出明确原因。

### FR-02 OCR 文字识别（P0）

**描述**：对图片执行中英文印刷体识别。

**输入**：图片标识、引擎标识、语言选项（中英混合/中文/英文）、图像预处理选项。

**处理**：
1. 根据引擎注册表加载对应 Provider；
2. 可选的预处理：灰度、二值化、旋转校正、缩放；
3. 调用引擎识别，统一转换为标准结果结构（全文、分块、置信度、耗时）；
4. 文本后处理：去除多余空白、合并断行、保留段落；
5. 结果写入数据库并返回。

**输出**：识别文本、分块明细、置信度、引擎、耗时。

**验收标准**：中英文印刷体图片可正确识别；引擎不可用时给出可读错误而非崩溃；识别结果可编辑。

### FR-03 结果编辑与复制（P0）

**描述**：用户可对识别结果进行修改并复制。

**处理**：编辑内容实时保存（防抖自动保存）；支持全选复制、一键复制、分段复制；保存时记录版本号与更新时间。

**验收标准**：刷新页面后编辑内容不丢失；复制内容与编辑器一致。

### FR-04 批量任务（P0）

**描述**：批量识别、进度展示、失败重试与取消。

**处理**：
1. 批次创建后由后台工作器异步执行；
2. 并发数可配置（默认 3，范围 1–8），通过信号量限流；
3. 每个任务项最多重试 N 次（默认 2），采用指数退避；
4. 进度通过 SSE 推送，断线时前端降级为轮询；
5. 支持取消未开始的任务、重试失败任务。

**输出**：批次状态（排队/运行/完成/部分失败/取消）、成功数、失败数、每项耗时与错误原因。

**验收标准**：100 张图片连续执行不崩溃；单张失败不影响整体；失败项可单独重试。

### FR-05 AI 智能处理（P0）

**描述**：对识别文本执行翻译、摘要、关键词提取与问答。

**输入**：文本、动作类型、目标语言、语气/长度等参数、AI 引擎。

**处理**：
1. 组合提示词模板与用户文本；
2. 调用兼容 OpenAI Chat Completions 协议的模型服务；
3. 记录输入输出、模型、耗时与 Token 用量；
4. 结果**不覆盖原文**，以独立结果面板展示，用户可选择替换或追加。

**输出**：处理结果文本、用量信息。

**验收标准**：翻译/摘要/关键词/问答四类功能均可返回结果；无密钥时演示引擎仍可完成流程演示；AI 失败不影响原文。

### FR-06 历史记录（P0）

**描述**：持久化保存识别与 AI 结果，支持检索与维护。

**处理**：
1. 保存文本、来源（文件/网页）、引擎、时间、字数、标签；
2. 支持关键词全文检索（SQLite FTS5，失败时降级 LIKE）、按引擎/来源/时间筛选；
3. 支持收藏、标签、删除与批量删除；
4. 分页返回。

**验收标准**：可按关键词检索到历史；删除后列表与详情同步失效。

### FR-07 导出（P1）

**描述**：将单条或多条记录导出为常用格式。

**支持格式**：TXT、CSV、Markdown、Word（.docx）、Excel（.xlsx）、ZIP（批量打包）。

**验收标准**：导出的 Word/Excel 可被 Office/WPS 正常打开；中文无乱码；CSV 带 UTF-8 BOM。

### FR-08 网页内容提取（P0）

**描述**：输入 URL，提取网页标题、作者、站点、正文与图片。

**处理**：
1. 校验 URL 协议（仅 http/https）并实施 SSRF 防护（禁止内网/环回/保留地址）；
2. 发起请求（超时、UA、最大响应体限制），识别编码；
3. 使用启发式算法去除导航、广告、脚本，提取正文容器；
4. 抽取 OpenGraph/JSON-LD 元数据与图片列表；
5. 保存提取记录，可一键转为文本文档。

**验收标准**：主流静态网页可提取出可读正文；非法 URL 与内网地址被拒绝；超时可控。

### FR-09 自动打开网页（P0）

**描述**：满足"提取网页后自动打开"的附加要求。

**处理**：
1. 提取成功后，前端根据用户开关自动在新标签页打开原始网页（`noopener,noreferrer`）；
2. 桌面模式下提供"用系统浏览器打开"接口，由后端调用系统默认浏览器；
3. 桌面启动器启动本地服务后，自动打开默认浏览器访问应用首页；
4. 提供"打开原文/打开图片所在目录"等快捷操作。

**验收标准**：开关开启时，提取完成自动打开原文且只打开一次；关闭时不打开；桌面启动器双击后浏览器自动打开应用。

### FR-10 设置中心（P1）

**描述**：配置引擎、密钥、任务参数与界面偏好。

**处理**：
1. OCR/AI 引擎选择与密钥配置，密钥仅在服务端保存，返回时脱敏；
2. 支持连接测试，返回延迟与可用性；
3. 并发数、重试次数、超时、单文件大小限制可配置；
4. 主题（浅色/深色/跟随系统）、界面语言（中文/English）本地保存；
5. 提供数据备份导出与恢复。

**验收标准**：密钥不会以明文返回前端；修改并发数后新批次生效；连接测试有明确结果。

### FR-11 统计看板（P2）

**描述**：展示识别量、成功率、平均耗时、引擎分布、近 7 日趋势。

**验收标准**：数据与数据库一致；无数据时展示空状态而非报错。

### FR-12 系统运维（P1）

**描述**：健康检查、版本信息、运行日志、数据清理。

**处理**：提供 `/api/health` 与 `/api/system/info`；日志滚动写入 `data/logs`；支持清理过期上传文件与历史记录。

**验收标准**：健康检查返回服务、数据库、引擎状态；异常时给出可定位信息。

## 4 非功能需求

### 4.1 性能需求

| 编号 | 指标 | 目标值 |
| --- | --- | --- |
| NFR-P1 | 首页首屏加载（本地） | ≤ 1.5s |
| NFR-P2 | 单张图片识别响应（演示/本地引擎） | ≤ 3s（不含网络） |
| NFR-P3 | 批量吞吐 | 100 张在 10 分钟内完成（视引擎而定） |
| NFR-P4 | 历史检索响应（1 万条记录） | ≤ 500ms |
| NFR-P5 | 并发任务数 | 可配置 1–8，默认 3 |
| NFR-P6 | 内存占用 | 空闲 ≤ 200MB |

### 4.2 安全需求

1. **密钥安全**：密钥仅存服务端数据库，接口返回脱敏值；不写入前端代码与打包资源。
2. **SSRF 防护**：网页抓取解析域名并拒绝私有网段、环回、链路本地地址；禁止重定向到内网。
3. **上传安全**：校验扩展名与真实图片格式，限制大小，文件名使用随机标识，避免路径穿越。
4. **XSS 防护**：前端渲染用户文本一律使用 `textContent` 或转义，禁止直接拼接 HTML。
5. **越权与遍历**：所有资源访问基于内部 ID 校验存在性，不暴露服务器绝对路径。
6. **依赖安全**：锁定主要依赖版本范围，CI 中执行基础静态检查。

### 4.3 可靠性与容错

1. 外部调用均设置连接与读取超时，失败可重试；
2. 批量任务状态持久化，服务重启后可恢复为"中断"状态并允许重试；
3. 单任务异常被捕获并记录，不中断工作器；
4. 数据库启用 WAL 模式，减少并发读写冲突；
5. 关键操作具备幂等性（重复提交不产生重复记录）。

### 4.4 易用性需求

1. 主要任务路径不超过 3 次点击；
2. 所有异步操作有明确的状态反馈（加载、进度、成功、失败原因）；
3. 支持键盘快捷键（粘贴上传、Ctrl+Enter 执行、Esc 关闭弹窗等）；
4. 错误提示使用用户可理解的自然语言，并给出处理建议；
5. 响应式布局，适配 1280px 及以上桌面屏幕，最小支持 1024px。

### 4.5 可维护性与可扩展性

1. 后端分层：接口层（api）—服务层（services）—提供者层（providers）—数据层（models/repositories）；
2. OCR/AI 引擎通过注册表与统一接口扩展，新增引擎无需修改业务逻辑；
3. 前端按页面与组件拆分 ES Module，状态集中管理；
4. 关键模块具备单元测试与接口测试，CI 自动执行；
5. 代码风格统一，使用类型注解与中文注释。

### 4.6 可移植性

1. 支持 Windows/Linux/macOS；
2. 数据目录可通过环境变量 `INSIGHTDESK_DATA_DIR` 重定向；
3. 提供 Dockerfile 与 docker-compose 配置（可选部署方式）；
4. 桌面版通过 PyInstaller 生成单文件可执行程序。

## 6 数据需求

### 6.1 实体关系概述

```text
batches 1 ─── n tasks
batches 1 ─── n documents
documents 1 ─── n ai_runs
documents 1 ─── n exports(逻辑记录，不单独建表)
web_extractions 1 ─── 0..1 documents
conversations 1 ─── n messages
settings（键值表）
```

### 6.2 数据字典（核心表）

**documents（文字资产）**

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | INTEGER PK | 主键 |
| title | TEXT | 标题（默认取文件名） |
| filename | TEXT | 原始文件名 |
| source_type | TEXT | image/web/manual |
| source_url | TEXT | 来源网页 |
| content | TEXT | 当前文本 |
| original_content | TEXT | 原始识别文本 |
| engine | TEXT | 识别引擎 |
| language | TEXT | 语言选项 |
| confidence | REAL | 平均置信度 |
| char_count | INTEGER | 字数 |
| status | TEXT | ok/failed |
| batch_id | INTEGER | 所属批次 |
| image_path | TEXT | 原图相对路径 |
| thumb_path | TEXT | 缩略图相对路径 |
| tags | TEXT | JSON 数组 |
| favorite | INTEGER | 是否收藏 |
| version | INTEGER | 编辑版本号 |
| created_at / updated_at | TEXT | ISO 时间 |

**batches（批次）**：id、name、status、total、succeeded、failed、concurrency、engine、options、created_at、started_at、finished_at。

**tasks（任务项）**：id、batch_id、filename、image_path、status、attempts、error、duration_ms、order_index、started_at、finished_at。

**ai_runs（AI 调用记录）**：id、document_id、action、provider、model、input_text、output_text、prompt、tokens_in、tokens_out、latency_ms、created_at。

**web_extractions（网页提取）**：id、url、title、author、site、content、images、word_count、status、error、created_at。

**settings（设置）**：key、value（JSON）、updated_at。

**conversations / messages（问答）**：会话标题、时间；消息角色、内容、时间。

### 6.3 数据保留与备份

- 上传原图默认保留 30 天，可通过设置清理；
- 历史记录不自动删除，由用户主动管理；
- 支持导出完整 JSON 备份与数据库文件下载（管理员操作）。
