## 2 数据模型

### 2.1 documents（文字资产）

| 字段 | 类型 | 约束/默认 | 说明 |
| --- | --- | --- | --- |
| id | INTEGER | PK | 主键 |
| title | VARCHAR(255) | 未命名文档 | 标题 |
| filename | VARCHAR(255) | NULL | 原始文件名 |
| source_type | VARCHAR(32) | image | image/web/manual |
| source_url | TEXT | NULL | 网页来源 |
| content | TEXT | "" | 当前文本 |
| original_content | TEXT | "" | 原始识别文本 |
| engine | VARCHAR(64) | "" | 引擎标识 |
| language | VARCHAR(32) | auto | 语言选项 |
| confidence | FLOAT | 0 | 平均置信度 |
| char_count | INTEGER | 0 | 有效字符数 |
| status | VARCHAR(24) | ok | ok/failed |
| error | TEXT | NULL | 失败原因 |
| batch_id | INTEGER | NULL | 所属批次 |
| image_path / thumb_path | TEXT | NULL | 相对路径 |
| tags | TEXT | [] | JSON 数组 |
| favorite | BOOLEAN | false | 收藏 |
| version | INTEGER | 1 | 编辑版本 |
| meta | TEXT | {} | 引擎耗时、演示标记等 |
| created_at / updated_at | VARCHAR(40) | ISO | 时间 |

索引：`source_type`、`engine`、`status`、`favorite`、`created_at`、`batch_id`。

### 2.2 batches / tasks

| 表 | 关键字段 | 状态机 |
| --- | --- | --- |
| batches | id、name、status、total、succeeded、failed、concurrency、engine、options | queued → running → succeeded / failed / partial / cancelled |
| tasks | id、batch_id、filename、image_path、status、attempts、error、duration_ms、document_id | pending → running → succeeded / failed / cancelled |

`tasks.batch_id` 外键 `ON DELETE CASCADE`；复合索引 `(batch_id, status)`。

### 2.3 其它表

- `ai_runs`：动作、引擎、模型、输入、输出、提示词、Token、耗时、状态。
- `web_extractions`：URL、最终 URL、标题、作者、站点、正文、图片、字数、状态。
- `conversations` / `messages`：多轮问答会话与消息。
- `settings`：键值表，值为 JSON 字符串。
- `documents_fts`：FTS5 虚拟表（trigram），由触发器与 `documents` 同步。

## 3 核心流程

### 3.1 批量任务时序

```text
Client            routes_tasks        task_service           Worker            SQLite/EventBus
  │ POST /batches     │                    │                    │                    │
  ├──────────────────>│  create_batch      │                    │                    │
  │                   ├───────────────────>│ 校验图片/建批次      │                    │
  │                   │                    ├───────────────────>│ 写入 batches/tasks  │
  │                   │                    │ start_batch        │                    │
  │<──────────────────┤                    ├─ 线程池提交 N 个 ──>│                    │
  │                   │                    │                    │ 标记 running        │
  │                   │                    │                    ├───────────────────>│
  │                   │                    │                    │ OCR + 文本后处理     │
  │                   │                    │                    │ 原子自增计数         │
  │                   │                    │<───────────────────┤ 发布事件            │
  │ GET /stream       │                    │                    ├───────────────────>│
  ├──────────────────>│ SSE 订阅事件总线    │                    │                    │
  │<──────────────────┤ data: {batch,...}  │                    │                    │
  │                   │                    │ 全部结束 → 终态      │                    │
```

**关键点**

1. 计数使用 `UPDATE batches SET succeeded = succeeded + 1`，避免并发丢失更新；
2. 单任务异常不向线程池抛出，记录 `error` 后继续；
3. 批次终态由 `_finalize_batch` 统一计算：`failed==0 → succeeded`，`succeeded==0 → failed`，否则 `partial`；
4. 取消只影响 pending 任务，运行中任务在下次检查批次状态时退出；
5. 服务重启后 `recover_interrupted` 将 queued/running 批次标记为 partial/failed，允许重试。

### 3.2 引擎选择与降级

```python
candidates = [requested, settings.ocr_engine, "mock"]
for name in candidates:
    if provider.available(settings):
        return provider
raise ProviderError("没有可用的 OCR 引擎")
```

降级时返回 `fallback_note`，并写入结果 `meta`，前端显示提示条。

### 3.3 OCR 后处理

1. `clean_text`：去控制字符、统一空白、压缩空行；
2. `merge_soft_wraps`：
   - 空行、句末标点、列表/标题前缀 → 保留换行；
   - 上一行较短（<12 字）且无逗号 → 视为标题，保留换行；
   - 上一行以逗号/冒号结尾、字符数 ≥ 24、或下一行以小写字母开头 → 合并；
   - 英文合并时补空格；
3. 统计字数（去空白）、检测语言、写入数据库。

### 3.4 历史检索

```text
查询长度 ≥ 3 且 FTS 可用 → documents_fts MATCH '"关键词"'
否则                    → title LIKE / content LIKE / tags LIKE
再叠加来源、引擎、收藏、标签、时间范围过滤
按 updated_desc / created_desc / chars_desc / title_asc 排序分页
```

FTS 查询异常时静默降级 LIKE，保证功能可用。

### 3.5 网页正文提取

1. **安全校验**：`validate_public_url`
   - 协议白名单 http/https；
   - 拒绝认证信息、非常用端口、`.local`；
   - 解析全部 A/AAAA 记录，任一为私有/环回/保留地址即拒绝。
2. **抓取**：`allow_redirects=False` 手动逐跳，每跳重新校验；`stream=True` 累计不超过 3MB；超时 `(5, 20)`。
3. **清洗**：移除 script/style/iframe/form 等；按 id/class 关键词移除广告、评论、导航；文本量 > 2000 的节点不删，避免误伤正文。
4. **容器打分**：`article/main/[role=main]/常见正文类名/body`，得分 = 文本长度 × (1 − 链接密度) + 段落数 × 80。
5. **正文抽取**：按 `h1-h4/p/li/blockquote/pre/td` 顺序提取、去重；不足 60 字回退 `get_text`。
6. **元数据**：OpenGraph、meta author、JSON-LD、`<title>`、`h1`。
7. **自动打开**：桌面模式后端调用 `webbrowser.open`；Web 模式返回 `auto_opened=false`，由前端新标签页打开。

### 3.6 AI 管线

```text
文本（≤12000 字，超出截断）
→ prompts.build_prompt(action, options)
→ Provider.process / chat
→ 记录 ai_runs（输入、输出、模型、Token、耗时）
→ 返回结果（不覆盖原文）
```

提示词动作：翻译、摘要、关键词、问答、润色、提纲。演示引擎基于词典、词频与句子检索生成确定性结果，并标记 `demo=true`。

### 3.7 导出

| 格式 | 实现 | 特性 |
| --- | --- | --- |
| TXT | 字符串拼接 | 含元信息分隔线 |
| CSV | `csv.writer` + UTF-8 BOM | 公式注入防护 |
| Markdown | 标题/引用/标签 | 适合知识库 |
| DOCX | python-docx | 中文字体、分页、元信息 |
| XLSX | openpyxl | 表头样式、冻结首行、筛选、列宽 |
| JSON | 完整字段 | 便于二次开发 |
| ZIP | 每条一个 txt + manifest | 批量归档 |

文件名通过 `slugify` 处理，`Content-Disposition` 同时提供 ASCII 回退与 UTF-8 文件名。

## 4 接口契约

### 4.1 统一约定

- 基础路径 `/api`；
- 成功：JSON；失败：`{"detail": "...", "code": "..."}`；
- 校验失败：422，`{"detail": "请求参数有误", "code": "validation", "errors": [...]}`；
- 时间为 ISO 8601（UTC+8）；
- 文件下载：`Content-Disposition: attachment; filename*=UTF-8''...`。

### 4.3 错误码

| HTTP | code | 场景 |
| --- | --- | --- |
| 400 | validation / security / web_extract | 参数、SSRF、网页不可提取 |
| 401/403 | auth | 云端引擎鉴权失败 |
| 404 | not_found | 记录、图片、批次不存在 |
| 422 | validation | Pydantic 校验失败 |
| 429/502 | upstream / provider_error | 限流、云端错误 |
| 500 | internal | 未处理异常（记录日志） |

## 5 前端设计

### 5.1 路由

| 路由 | 页面 | 关键依赖 |
| --- | --- | --- |
| `#/dashboard` | 工作台 | stats、health |
| `#/ocr` | OCR 工作台 | engines、upload、recognize、history |
| `#/batch` | 批量任务 | batches、SSE、retry、cancel |
| `#/ai` | AI 助手 | actions、providers、process、chat |
| `#/history` | 历史记录 | history、tags、export |
| `#/web` | 网页提取 | web extract、open、history |
| `#/settings` | 设置 | settings、test、cleanup |
| `#/help` | 帮助 | 静态内容 |

### 5.2 状态与组件

- `store.js`：主题、语言、健康状态、引擎缓存、活动批次；
- `router.js`：哈希解析、页面生命周期、卸载清理；
- 组件：`toast`、`modal`、`uploader`、`editor`、`chart`、`pagination`、`commandPalette`、`exportDialog`；
- 所有用户文本使用 `textContent`；唯一使用 `innerHTML` 的场景是静态图标与已转义内容。

### 5.3 SSE 与降级

- 全局单一 `EventSource` 连接 `/api/tasks/stream`；
- 服务端发送命名事件（batch_update、task_succeeded 等）；
- `app.js` 将事件转发为 `window` 自定义事件，批次页订阅；
- 连接失败自动重连，批次页另有 4 秒轮询兜底。

### 5.4 响应式与可访问性

- 布局断点：1280 / 1100 / 960 / 860 / 700 / 560；
- 侧边栏在窄屏变为抽屉；
- 支持键盘导航、`aria-label`、焦点可见、`prefers-reduced-motion`。

## 8 错误处理与日志

- 全局异常处理器：ProviderError → 502、SecurityError/WebExtractError → 400、参数错误 → 422、未知 → 500；
- 日志输出到控制台与 `data/logs/app.log`（2MB 滚动，保留 3 份）；
- 慢请求（>2s）记录警告；
- 批量任务失败记录批次、任务、重试次数与原因。

## 9 已知限制

1. 动态渲染（依赖 JavaScript）的网页无法直接提取；
2. 演示引擎结果为模拟文本，仅用于流程演示；
3. 未内置用户体系，局域网部署需通过网络层访问控制；
4. 桌面版首期仅提供 Windows 构建脚本。
