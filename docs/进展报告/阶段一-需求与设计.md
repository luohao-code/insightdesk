## 三、需求基线摘要

### 3.1 产品定位

面向学生与办公人群的轻量文字资产工作台：**图片/网页 → OCR → 文本 → AI 加工 → 历史资产 → 导出**。

### 3.2 功能范围

**必做（P0）**：图片导入、中英文 OCR、结果编辑复制、批量任务与重试、AI 翻译/摘要/关键词/问答、历史检索、网页提取、提取后自动打开网页、桌面启动器自动打开浏览器。

**应当（P1）**：多格式导出（TXT/CSV/Markdown/Word/Excel/ZIP）、设置中心、系统运维接口。

**可选（P2）**：统计看板、命令行工具、Docker 部署。

**明确不做**：本地大模型训练、手写/公式/复杂表格、自动排版报告、视频理解、用户系统与支付。

### 3.3 关键非功能指标

- 100 张图片批量执行不崩溃，失败项可单独重试；
- 历史检索（1 万条）响应 ≤ 500ms；
- 密钥不出现在前端与接口响应中；
- 网页抓取具备 SSRF 防护；
- 代码规模 ≥ 15000 行，测试全部通过。

> 完整需求见 [软件需求规格说明书](../01-软件需求规格说明书.md)。

## 四、架构与技术选型

| 层次 | 选型 | 理由 |
| --- | --- | --- |
| 前端 | 原生 ES Module + 自研组件 + CSS 设计令牌 | 无构建依赖、离线可用、便于展示综合技术能力 |
| 后端 | Python 3.12 + FastAPI | 异步、类型友好、自动生成 API 文档 |
| 数据层 | SQLAlchemy 2.0 + SQLite（WAL） | 零配置、易部署、支持 FTS5 全文检索 |
| OCR | RapidOCR（本地）/ 百度 OCR / 腾讯 OCR / 演示引擎 | 可插拔，兼顾离线与准确率 |
| AI | OpenAI 兼容协议（DeepSeek/Kimi/智谱/通义） | 一套适配多平台，降低耦合 |
| 任务 | 线程池 + 信号量 + 指数退避 | 控制并发与限流，满足批量稳定性 |
| 实时进度 | SSE（EventSource），轮询降级 | 实现简单、浏览器兼容好 |
| 部署 | uvicorn / Docker / PyInstaller | 覆盖服务器与桌面两种形态 |

系统采用四层结构：**接口层 → 服务层 → 提供者层 → 数据层**。OCR 与 AI 通过注册表统一管理，新增引擎只需实现统一接口并注册，不影响上层业务。
