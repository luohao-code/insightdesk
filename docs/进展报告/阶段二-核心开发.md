## 四、关键问题与解决

### 4.1 并发计数丢失（严重）

**现象**：3 张图片的批次偶尔显示"成功 2 / 总数 3"，批次却已结束。

**根因**：多个工作线程各自读取 `batch.succeeded`，在内存中 `+1` 后写回，发生丢失更新。

**解决**：改为数据库原子自增：

```sql
UPDATE batches SET succeeded = succeeded + 1 WHERE id = :id
```

失败计数同理；重试时按任务实际状态重新计算失败数。补充并发测试后稳定通过。

### 4.2 SSE 断线与重复连接

- 服务端每 15 秒发送注释心跳，避免代理断开；
- 浏览器 `EventSource` 自动重连；
- 前端全局只维护一个连接，通过自定义事件分发给页面；
- 批次页保留 4 秒轮询兜底，SSE 异常时仍可看到进度。

### 4.3 网页抓取的 SSRF 风险

仅校验初始 URL 不够，攻击者可用公网 URL 302 到内网。实现：

- 关闭自动重定向，手动逐跳处理；
- 每一跳重新解析域名并校验全部 IP；
- 限制端口、响应体大小与超时；
- 拒绝 `file://`、含认证信息的 URL。

### 4.4 OCR 软换行合并过度

初版把所有相邻行合并，导致标题与正文粘连。改进为启发式：

- 空行、句末标点、列表/标题前缀保留换行；
- 短行（<12 字）视为标题；
- 仅在上一行以逗号结尾、长度 ≥ 24 或下一行小写开头时合并。

使用 RapidOCR 对示例图验证，标题层级得以保留。

### 4.5 密钥脱敏与"保持原值"

设置接口返回 `••••••••`。若用户只提交掩码，后端视为"保持不变"并幂等返回，避免误清空密钥。
